# [GP Implementation Plan] 점포 환경개선 추진계획서 AI 자동작성기 영구 강제 원칙

> **문서 버전**: v1.0.0 (독립 헌법)  
> **적용 대상**: `GP Implementation Plan/plan-generator.html` 및 로컬 동기화 파일  
> **소속 및 관리**: `GP Implementation Plan/` 독립 전용 강제 원칙 (간판지원단 메인 포털과 완전 분리)  
> **검증 도구**: `GP Implementation Plan/verify-plan.js` (`npm run verify:plan`)

## 🏛️ [독립 절대 강제 원칙] 점포 추진계획서 6대 절대 준수 법칙

### 제1원칙: 400자 미만 부실 단문 작성 0% 절대 차단 (Zero Under-400 chars)
1. "점포 환경개선 추진 계획"은 경기도시장상권진흥원(경상원) 및 공단 공공 심사 서류의 핵심 평가 척도이므로, 공백 및 줄바꿈 포함 **"최소 400자 이상"**이어야 한다.
2. 400자 미만(예: 200~300자대)으로 성의 없이 작성된 글을 사용자 화면에 그대로 노출하는 행위를 100% 영구 엄격 금지한다.
3. 글의 구성은 반드시 다음 4단계 행정 표준 규격을 엄격히 준수해야 한다:
   - `1. 사업체 소개 :` (업종 특성, 점포 역사, 영업 가치 - 약 110~125자)
   - `2. 환경개선 추진 배경 :` (노후 간판의 구체적 노후 상태 및 시인성 저하 - 약 110~125자)
   - `3. 개선 사업의 필요성 :` (안전사고 위험, 영업 손실, 간판 교체 시급성 - 약 110~125자)
   - `4. 기대효과 :` (시인성 확보, 점포 미관 개선, 매출 증대 및 사업장 재기 - 약 110~125자)

### 제2원칙: 400자 미달 시 자동 확장 엔진 강제 발동 (Auto-Expansion Engine)
1. Gemini AI의 1차 생성 결과물이 400자 미만일 경우, 시스템은 결과를 화면에 즉시 노출하지 않고 **백그라운드에서 자동 확장 엔진(`initialPlan.length < 400`)을 즉각 강제 발동**해야 한다.
2. 각 항목의 사연과 설명을 더 풍부하고 품격 있게 보강하는 2차 정밀 확장 프롬프트(`expansionPrompt`)를 실행하여, **반드시 445~485자의 완성도 높은 글**로 확충한 후에만 화면에 표시한다.

### 제3원칙: 500자 공단 전산 한도 준수 및 4. 기대효과 100% 종결 의무 (Zero Truncation)
1. 경상원 및 공단 전산 입력 한도인 **"최대 500자 이내"**를 엄격히 사수한다.
2. 어떠한 경우에도 글이 중간에 뚝 끊긴 채 500자로 잘려 나가는 것을 영구 금지한다.
3. 500자를 초과할 위험이 있을 경우, 반드시 **"4. 기대효과 :"**의 마지막 문장이 완전한 종결어미와 마침표(.)로 끝나는 지점(`lastPeriod >= 400`)에서 안전하게 마감되어야 한다.

### 제4원칙: 현장 보충 설명("기타 입력") 100% 문맥 반영 의무 (bizExtraNotes Reflection)
1. "개업년도 또는 운영기간"과 "사업장 주소" 사이에 위치한 **"기타 입력(`bizExtraNotes`)"**란의 내용을 AI 프롬프트에 100% 필수 연동한다.
2. 점주가 기재한 점포의 상세 사연, 업종 보충 설명, 장인정신/기술력, 현장 애로사항을 글 속에 자연스럽게 녹여내어, 천편일률적인 글이 아닌 각 점포만의 독창적이고 진정성 넘치는 명문으로 완성한다.

### 제5원칙: 노후 간판 현장 사진 3장 육안 팩트 기반 절대 진실성 원칙 (Fact-Based Vision)
1. 업로드된 노후 간판 사진 3장의 실제 육안 상태(백화, 탈색, 파손, 조명 불량 등)를 AI 비전 기술로 있는 그대로 판독하여 서술한다.
2. 사진의 실제 상태와 다른 과장이나 허위 기재를 100% 영구 엄격 금지한다.

### 제6원칙: 브라우저 재부팅 및 로컬 캐시 초기화 시에도 API 키 100% 영구 보존 원칙
1. 사용자가 컴퓨터를 껐다 켜거나 브라우저 캐시를 삭제하더라도, 로컬 작업기 환경에서 Gemini API 키를 매번 다시 입력하지 않도록 100% 영구 보존되어야 한다.
2. 단, GitHub 공개 저장소에는 보안을 위해 빈 템플릿으로 유지하고, 로컬 구동 파일에만 자동 주입/유지되는 2중 보안 파이프라인을 준수한다.

## 🔍 [전용 검문소] GP Implementation Plan 검증 체계
- **검증 스크립트**: `GP Implementation Plan/verify-plan.js`
- **실행 명령**: `npm run verify:plan`
- **필수 통과 항목**:
  1. `bizExtraNotes` (기타 입력) 폼 및 이벤트 바인딩 존재 검증
  2. `initialPlan.length < 400` 자동 확장 엔진 및 `expansionPrompt` 존재 검증
  3. `lastPeriod >= 400` 종결 마침표 단위 안전 마감 로직 검증
  4. 500자 실시간 카운터 및 4개 항목(1. 사업체 소개 ~ 4. 기대효과) 규격 검증
